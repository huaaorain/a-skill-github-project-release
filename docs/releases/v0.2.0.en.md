## Summary

`0.2.0` adds release-time version consistency protection and a consistent presentation rule for optional capabilities. Current-version locations such as README badges, banner SVGs, and text-based screenshots must now be registered in `version_surfaces`; preflight blocks publishing when any location is missing or disagrees with the target tag. Optional login, model, or extension capabilities use a `*` marker across localized pages.

## Highlights

- Added `version_surfaces` to `.github/release-spec.json`, using a file path and a regular expression with a named capture group for each current-version display.
- `preflight` verifies that every version surface exists, matches the target tag, and no longer contains a stale version.
- Added an optional-capability convention to the README template and release guidance: prefix non-required features with `*` and explain that core features work without them.
- Updated the Simplified Chinese, Traditional Chinese, and English project pages to describe version-surface preflight and optional capability markers.
- Corrected the skill banner from the stale `v0.1.0` value to the current version and added it to automated checks.

## Fixes

- Fixed cases where README badges were updated while a banner image still displayed an older version.
- Prevented stale versions in text banners, hero SVGs, or screenshots from reaching a release.
- Prevented optional GitHub login, local LLM, or extension capabilities from being described as mandatory for installing the core project.

## Compatibility and upgrade

- Existing projects must add at least one `version_surfaces` entry to `.github/release-spec.json` before `preflight` can pass.
- Register every localized README version badge and every SVG that displays the current version.
- Release assets, tags, manifest formats, and existing project data require no migration.
- Text preflight cannot read a version rendered inside a PNG or JPEG, so those screenshots still require a visual review.

## Platforms and limitations

- Windows, macOS, and Linux.
- GitHub.com and the GitHub REST API.
- Version-surface checks only apply to UTF-8 text files; use narrow patterns so historical release catalogs and notes are not treated as current-version surfaces.
