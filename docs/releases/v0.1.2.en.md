## Summary

`0.1.2` adds a clear semantic icon system to project pages generated by the skill. Inspired by the icon-led feature presentation in `prompt-optimizer`, it uses a small set of stable meanings for features, installation, safety, downloads, and verified advantages while preserving the existing feature table and CJK label wrapping fix.

## Highlights

- Added a README icon convention: `✨` for features, `🚀` for installation or release workflow, `🛡️` for safety and privacy, `📦` for downloadable assets, and `✅` only for advantages backed by implementation, tests, or compatibility evidence.
- Added a `✅ Key advantages` block to the README template and consistent icons to its major sections.
- Updated the Simplified Chinese, Traditional Chinese, and English project pages with the same icon meanings and section structure.
- Added explicit HTML anchors to icon-prefixed headings used by page navigation so the links remain stable.
- Preserved the feature table and narrow no-break spacing used to prevent short CJK labels from wrapping into orphaned characters.

## Fixes

- Ensured the icon idea is implemented in the template and actual project pages instead of remaining documentation-only inspiration.
- Prevented `✅` from being used as decoration or implying that an unverified feature is confirmed.
- Prevented icon-prefixed headings from breaking in-page navigation to capabilities, installation, and all releases.

## Compatibility and upgrade

- Upgrading from `0.1.1` requires no project-data migration or changes to existing release assets.
- The release manager commands, release manifest format, and localization configuration remain compatible.
- Existing projects can adopt the new template incrementally; previously generated pages do not need to be rewritten.

## Platforms and limitations

- Windows, macOS, and Linux.
- GitHub.com and the GitHub REST API.
- Operating systems and fonts may render color emoji slightly differently; explicit anchors keep navigation independent of emoji rendering.

## Verification

- All 9 offline release manager tests passed.
- The skill structure validation passed.
- All 4 in-page navigation links in each localized README resolve to explicit anchors.
