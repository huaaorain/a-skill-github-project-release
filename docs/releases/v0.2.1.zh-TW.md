## 版本摘要

`0.2.1` 增加上傳前安全檢查，並建立授權選擇流程。新版會掃描原始碼、未追蹤檔案、未推送 Git 歷史與 Release ZIP 中的常見憑證，並在專案缺少授權時要求使用者明確選擇。本 skill 自身採用 PolyForm Noncommercial License 1.0.0。

## 主要更新

- 新增 `security-check`，可掃描已追蹤、已暫存、未追蹤但未忽略、未推送 Git 歷史以及 ZIP Release 附件。
- 檢查常見憑證檔案名稱、私鑰、GitHub/雲端服務/AI/支付平台 Token，以及密碼、API Key、Token 字面值。
- 掃描結果只報告位置和類型，不輸出命中的密鑰值。
- `preflight` 自動執行完整安全掃描，發現真實憑證時阻止發佈。
- 首次公開上傳前列出 MIT、Apache-2.0、BSD-3-Clause、MPL-2.0、GPL-3.0-only、AGPL-3.0-only 等常用授權，並要求使用者自行選擇。
- 明確區分 OSI 開源授權和來源可見授權；禁止銷售或商業使用時不會誤標為開源。
- 本 skill 採用 PolyForm Noncommercial License 1.0.0，並加入 `Required Notice` 署名。

## 問題修正

- 安全檢查從少量已追蹤檔案擴展為原始碼、Release ZIP 和待推送歷史的完整檢查。
- 阻止 `.env`、私鑰、Token 檔案和常見硬編碼憑證進入 Git 或 Release 附件。
- 避免在沒有授權或使用者未確認授權條款時公開發佈。

## 相容性與升級

- 從 `0.2.0` 升級不需要遷移 `version_surfaces` 或 Release 清單。
- 既有專案可先執行 `security-check --root .` 做原始碼掃描，再執行 `security-check --spec .github/release-spec.json` 檢查附件。
- `.env.example`、`.env.sample` 和 `.env.template` 可以使用佔位符，但不能包含真實憑證。
- 本專案不是 OSI 開源專案；商業用途需要單獨授權，商業使用方不應沿用「開源」描述。

## 平台與限制

- Windows、macOS 與 Linux。
- GitHub.com 與 GitHub REST API。
- 自動掃描無法證明倉庫絕對沒有密鑰，也不能讀取 PNG/JPEG 中可見的敏感資訊或程式內部的加密資源。
