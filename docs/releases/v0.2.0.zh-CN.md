## 版本摘要

`0.2.0` 增加发布前版本一致性保护，并统一可选功能的展示规则。README 徽章、横幅 SVG、文字型截图等当前版本显示位置现在必须登记到 `version_surfaces`；任一位置缺失或与目标标签不一致时，预检会阻止发布。可选登录、模型或扩展功能则在三语页面中使用 `*` 标记。

## 主要更新

- `.github/release-spec.json` 新增 `version_surfaces`，用文件路径和带命名捕获组的正则表达式登记当前版本显示位置。
- `preflight` 会检查每个版本显示位是否存在、是否匹配以及是否仍为旧版本。
- README 模板与发布说明规则加入可选功能标记：非必需功能标题前使用 `*`，并解释核心功能无需安装该能力。
- 简体中文、繁體中文和 English 项目首页同步展示版本一致性预检和可选功能标记能力。
- skill 横幅从过期的 `v0.1.0` 修正为当前版本，并纳入自动预检。

## 问题修复

- 修复 README 徽章已更新、横幅图片仍显示旧版本的问题。
- 避免文字型横幅、Hero SVG 或截图中的版本号在发布时漏改。
- 避免把可选的 GitHub 登录、本地 LLM 或扩展能力误写成安装核心项目的必要条件。

## 兼容性与升级

- 现有项目的 `.github/release-spec.json` 需要新增至少一个 `version_surfaces` 条目后，才能通过 `preflight`。
- 建议每个语言 README 的版本徽章和所有包含当前版本文字的 SVG 都单独登记。
- Release 附件、标签、清单格式和已有项目数据不需要迁移。
- PNG 或 JPEG 截图中的版本文字无法由文本预检读取，发布前仍需人工检查。

## 平台与限制

- Windows、macOS 与 Linux。
- GitHub.com 与 GitHub REST API。
- 版本表面检查只适用于 UTF-8 文本文件；历史版本目录和发布记录应使用范围更窄的匹配规则排除。

## 验证结果

- release manager 的 10 项离线测试全部通过。
- 新增回归测试确认横幅版本过期时预检会失败。
- skill 结构校验与 release spec JSON 校验通过。
- skill 自身的三个 README 徽章和横幅均与 `0.2.0` 一致。
