## 版本摘要

`0.2.0` 增加發佈前版本一致性保護，並統一可選功能的展示規則。README 徽章、橫幅 SVG、文字型截圖等目前版本顯示位置現在必須登記到 `version_surfaces`；任一位置缺少或與目標標籤不一致時，預檢會阻止發佈。可選登入、模型或擴充功能則在三語頁面中使用 `*` 標記。

## 主要更新

- `.github/release-spec.json` 新增 `version_surfaces`，以檔案路徑和帶命名擷取群組的正規表達式登記目前版本顯示位置。
- `preflight` 會檢查每個版本顯示位置是否存在、是否匹配以及是否仍為舊版本。
- README 範本與發佈說明規則加入可選功能標記：非必要功能標題前使用 `*`，並說明核心功能無需安裝該能力。
- 简体中文、繁體中文和 English 專案首頁同步展示版本一致性預檢與可選功能標記能力。
- skill 橫幅從過期的 `v0.1.0` 修正為目前版本，並納入自動預檢。

## 問題修正

- 修正 README 徽章已更新、橫幅圖片仍顯示舊版本的問題。
- 避免文字型橫幅、Hero SVG 或截圖中的版本號在發佈時漏改。
- 避免把可選的 GitHub 登入、本地 LLM 或擴充能力誤寫成安裝核心專案的必要條件。

## 相容性與升級

- 既有專案的 `.github/release-spec.json` 需要新增至少一個 `version_surfaces` 條目後，才能通過 `preflight`。
- 建議每個語言 README 的版本徽章和所有包含目前版本文字的 SVG 都單獨登記。
- Release 附件、標籤、清單格式和既有專案資料不需要遷移。
- PNG 或 JPEG 截圖中的版本文字無法由文字預檢讀取，發佈前仍需人工檢查。

## 平台與限制

- Windows、macOS 與 Linux。
- GitHub.com 與 GitHub REST API。
- 版本表面檢查只適用於 UTF-8 文字檔案；歷史版本目錄和發佈記錄應使用範圍更窄的匹配規則排除。
