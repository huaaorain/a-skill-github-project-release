## 版本摘要

`0.2.1` 增加上传前安全检查，并建立许可证选择流程。新版会扫描源码、未跟踪文件、未推送 Git 历史和 Release ZIP 中的常见凭据，同时在项目缺少许可证时要求用户明确选择。本 skill 自身采用 PolyForm Noncommercial License 1.0.0。

## 主要更新

- 新增 `security-check`，可扫描已跟踪、已暂存、未跟踪但未忽略、未推送 Git 历史以及 ZIP Release 附件。
- 检查常见凭据文件名、私钥、GitHub/云服务/AI/支付平台 Token，以及密码、API Key、Token 字面量。
- 扫描结果只报告位置和类型，不输出命中的密钥值。
- `preflight` 自动运行完整安全扫描，发现真实凭据时阻止发布。
- 首次公开上传前列出 MIT、Apache-2.0、BSD-3-Clause、MPL-2.0、GPL-3.0-only、AGPL-3.0-only 等常用协议，并要求用户自行选择。
- 明确区分 OSI 开源许可和来源可见许可；禁止销售或商业使用时不会误标为开源。
- 本 skill 采用 PolyForm Noncommercial License 1.0.0，并加入 `Required Notice` 署名。

## 问题修复

- 安全检查从少量已跟踪文件扩展为源码、Release ZIP 和待推送历史的完整检查。
- 阻止 `.env`、私钥、Token 文件和常见硬编码凭据进入 Git 或 Release 附件。
- 避免在没有许可证或用户未确认许可条款时公开发布。

## 兼容性与升级

- 从 `0.2.0` 升级不需要迁移 `version_surfaces` 或 Release 清单。
- 现有项目可先运行 `security-check --root .` 做源码扫描，再运行 `security-check --spec .github/release-spec.json` 检查附件。
- `.env.example`、`.env.sample` 和 `.env.template` 可以使用占位符，但不能包含真实凭据。
- 本项目不是 OSI 开源项目；商业用途需要单独授权，商业使用方不应沿用“开源”描述。

## 平台与限制

- Windows、macOS 与 Linux。
- GitHub.com 与 GitHub REST API。
- 自动扫描无法证明仓库绝对没有密钥，也不能读取 PNG/JPEG 中可见的敏感信息或程序内部的加密资源。
