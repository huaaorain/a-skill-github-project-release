# Feature images and screenshots

The functional introduction must contain at least one meaningful local image. Choose evidence by project type:

- Desktop GUI: capture the primary workflow and one differentiating feature or state.
- Web app: capture the real interface at a useful viewport; include a mobile view when responsive behavior matters.
- CLI: capture a representative command and result, or render a terminal recording into a GIF.
- Library or backend service: generate a clear architecture, request-flow, or usage diagram.
- Dataset or file-format tool: show a real input/output example.

## Evidence quality

- Use non-sensitive demo data or a documented safe demo mode.
- Remove personal paths, tokens, email addresses, customer data, debug overlays, and unrelated desktop content.
- Keep screenshots legible at GitHub's content width.
- Use a consistent theme and crop.
- Caption each image with the feature or workflow it proves.
- Store files under `docs/assets/` with descriptive names.
- Verify that README paths render on GitHub and have useful alt text.

## Fallback

If the project cannot be run safely, use screenshots supplied by the user or generate a clearly labeled architecture/flow diagram from source and documentation. A generated illustration may support the page, but it must not be labeled as a screenshot or imply functionality that does not exist.

Do not upload screenshots and diagrams as Release assets unless they are standalone end-user downloads. Repository documentation images belong in Git.
